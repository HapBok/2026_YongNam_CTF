# 문제 캡처로 TOML 자동 생성하기

문제별 폴더에 첨부파일과 설명 화면 캡처를 넣고 `make-toml`을 실행하면 `challenge.toml`을 생성합니다. 제목·유형·설명·접속 정보·문제 페이지 주소를 추출하며, 문제 ID는 이미지가 아니라 폴더 이름으로 고정합니다. `scope.toml`은 생성하거나 변경하지 않습니다.

## 폴더 준비

```text
CTF/2026_영남권 CTF/문제/
  c001/
    info/
      01.png
      02.png
    files/
      문제에서_다운로드한_파일.zip
  c002/
    info/
      01.jpg
    files/
```

`info/`에는 문제 제목·유형·설명·접속 정보가 보이는 캡처만 둡니다. 분석 대상인 이미지 파일은 `files/`에 둡니다. 캡처 순서는 파일 이름순이므로 `01.png`, `02.png`처럼 이름을 붙이세요. 캡처는 문제당 PNG/JPEG 최대 5장, 장당 10 MiB, 합계 25 MiB입니다. 잘린 글자·주소·포트를 추측해 채우지 않습니다.

`files/`에는 원본 첨부파일을 넣습니다. 자동 생성기는 파일명·크기 목록만 참조하고 실행하거나 압축을 풀지 않습니다. 첨부파일이 없는 문제는 빈 `files/`를 사용하며, 폴더가 없으면 성공적인 TOML 생성 때 빈 폴더를 만듭니다. 다운로드 중인 `.part`, `.crdownload` 등이 남아 있으면 먼저 다운로드를 완료하세요.

복사 가능한 설명은 선택적으로 `c001/description.txt`에도 넣을 수 있습니다. 캡처와 텍스트가 충돌하면 검토 대상으로 처리합니다. 비밀번호·토큰·쿠키는 캡처에서 가리세요.

## 한 번에 생성

PowerShell에서 `wsl.exe -d Ubuntu`로 들어간 다음, Ubuntu 관리 터미널에서 실행합니다.

```bash
cd '/mnt/c/Users/happy/Ready_Google/CTF/2026_영남권 CTF/Agent Engineering'
python3 ctfctl.py make-toml '/mnt/c/Users/happy/Ready_Google/CTF/2026_영남권 CTF/문제' --batch
```

이 명령은 각 하위 문제 폴더의 `challenge.toml`을 생성합니다. 폴더 이름은 `c001`, `c002`처럼 영문 소문자로 시작하는 소문자·숫자·하이픈 조합을 사용합니다. 수동으로 TOML을 작성할 필요는 없습니다.

TOML 생성은 실제 모델을 호출하므로 구독 사용량이 발생합니다. 기본은 GPT-6 Luna Medium, Standard, Daybreak Off입니다. 기본 모델이 제공되지 않을 때만 기존 Intake fallback인 GPT-6.1 Sol Medium을 사용합니다. 429·인증 오류·시간 초과는 무한 재시도하지 않습니다. `scope.toml`이나 `init-run` 없이도 로컬 문제 메타데이터를 준비할 수 있지만, 풀이 실행에는 기존 허용 범위와 사전 점검이 필요합니다.

폴더를 상시 감시하는 기능은 아닙니다. 새 캡처와 파일을 넣은 뒤 위 명령을 실행합니다. 기존 `challenge.toml`은 `EXISTS`로 표시하고 모델을 재호출하거나 덮어쓰지 않으므로 같은 상위 폴더에 반복 실행할 수 있습니다. 기존 TOML과 다른 ID를 지정하면 오류로 중단합니다.

## 한 문제만 생성

```bash
python3 ctfctl.py make-toml '/mnt/c/Users/happy/Ready_Google/CTF/2026_영남권 CTF/문제/c003'
```

폴더 이름 대신 별도 ID가 필요한 단일 문제에는 `--id c003`을 지정할 수 있습니다. Batch에서는 ID가 폴더 이름으로 고정됩니다. 해당 ID가 운영자가 작성한 `scope.toml`의 허용 목록과 일치해야 실제 풀이로 등록됩니다.

## 결과 확인과 문제 등록

| 출력 | 의미와 다음 행동 |
|---|---|
| `CREATED` | `challenge.toml` 생성 완료. 내용과 연결 정보를 빠르게 확인하고 등록 |
| `EXISTS` | 기존 TOML 보존. 수정이 필요하면 운영자가 검토 후 편집 |
| `REVIEW_REQUIRED` | `challenge.review-....toml`만 생성. 내용을 확인·수정한 뒤 직접 `challenge.toml`로 확정 |
| `ERROR` | 파일 배치·다운로드·이미지 형식·모델 오류 등을 해결한 뒤 다시 실행 |

읽기 어려운 글자, 잘린 설명, 연결 정보 충돌, 낮은 추출 신뢰도, 민감정보 또는 시스템 조작 지시가 있으면 검토용 초안만 생성합니다. 초안은 자동 등록되지 않습니다. 원본 캡처·첨부파일과 기존 TOML은 덮어쓰지 않습니다.

접속 정보는 `nc 주소 포트`, `주소:포트`, 완전한 URL처럼 관계가 보존된 표현으로 저장합니다. 주소와 포트가 별도 조각으로 출력되거나 지원하지 않는 접속 표현이면 신뢰도 점수가 높더라도 검토용 초안으로 분리합니다.

검토가 필요한 폴더에 아직 `challenge.toml`이 없으면 전체 Batch 등록은 그 폴더에서 멈출 수 있습니다. 해당 초안을 먼저 확정하거나 준비된 문제만 개별 등록하세요.

허용 범위 초기화·로컬 시험·실제 사전 점검이 완료된 Run에서는 다음 명령으로 등록합니다.

```bash
python3 ctfctl.py import-batch '/mnt/c/Users/happy/Ready_Google/CTF/2026_영남권 CTF/문제' --skip-existing
python3 ctfctl.py status
```

`--skip-existing`는 DB에 이미 등록된 문제 ID만 건너뜁니다. 기존 문제를 새 내용으로 갱신하지 않습니다. 새 문제의 `challenge.toml`은 기존 허용 범위를 통과해야 합니다. Batch 중간 실패 시 앞의 문제는 이미 등록되어 있을 수 있습니다.

Worker를 아직 시작하지 않았다면 PowerShell에서 원래 프로젝트의 `scripts/launch-8.ps1`을 실행합니다. 이미 실행 중이면 새로 등록된 문제는 빈 Worker에 자동 배정되므로 실행기를 다시 켜지 않습니다.

## 동시 실행과 복구

TOML 생성은 문제 풀이와 같은 SQLite 슬롯 장부에서 한 슬롯을 예약합니다. 8개가 모두 실행 중이면 슬롯이 빌 때까지 기다립니다. 풀이 Worker 탭을 닫을 필요는 없으며, TOML 생성과 풀이를 합쳐 동시에 8개 Agent Run을 넘지 않습니다. 상태 감시에 `metadata waiting/running`과 Profile이 표시됩니다.

생성기는 한 번에 하나만 실행합니다. 정상 중단 시 모델 프로세스 그룹을 종료하고 슬롯을 반환합니다. 생성기를 강제로 죽여 예약이 남으면 자동으로 슬롯을 풀지 않습니다. 살아 있는 생성기와 풀이를 먼저 정상 종료하고 상태를 확인한 뒤 기존 `recover` 절차를 사용하세요. 프로세스 신원을 확인할 수 없는 고아 그룹은 수동 검토 대상으로 남습니다.

설명 화면은 신뢰할 수 없는 데이터입니다. 캡처에 적힌 명령·모델 변경·범위 확장 지시를 실행하지 않습니다. 실제 이미지 입력에는 [공식 CLI의 이미지 첨부 옵션](https://learn.chatgpt.com/docs/cli/reference)을 사용합니다. 생성 결과를 읽어 확인할 책임까지 OCR이 대체하지는 않습니다.

이번 기능 추가로 코드 지문이 바뀌었으므로 기존 실제 사전 점검 결과는 새 버전에 사용할 수 없습니다. 실제 운영 전에 현재 코드의 로컬 acceptance와 `doctor --live`를 확인하세요. 상세 시작·중단·종료 절차는 [CLI 시작과 운영 매뉴얼](cli-manual-ko.md)을 참고하세요.
